# HTTP Security Analysis – SPL Queries

## Overview

HTTP logs provide valuable visibility into web traffic and can support investigations involving unusual requests, abnormal traffic patterns, suspicious response codes, and potentially malicious activity.

This section contains SPL searches for analyzing HTTP activity and identifying patterns that may require further investigation.

> **Note:** Field names can vary depending on the HTTP log source and Splunk configuration. The searches below use common field names and can be adapted to the actual ingested dataset.

---

## 1. Search HTTP Events

A basic search can be used to identify HTTP-related events.

```spl
index=main sourcetype=http
| table _time src_ip dest_ip method uri status
| sort - _time
```

### Purpose

Provides a basic view of:

- Event timestamp
- Source IP
- Destination IP
- HTTP method
- Requested URI
- HTTP response status

---

## 2. Analyze HTTP Methods

Identify the HTTP methods observed in the environment.

```spl
index=main sourcetype=http
| stats count by method
| sort - count
```

### Investigation Value

This can help identify:

- Common request methods
- Unusual methods
- Changes in normal HTTP behavior

---

## 3. Analyze HTTP Response Codes

Group HTTP events by response status.

```spl
index=main sourcetype=http
| stats count by status
| sort - count
```

### Purpose

This provides visibility into:

- Successful requests
- Client errors
- Server errors
- Unusual response patterns

---

## 4. HTTP Requests by Source IP

Analyze request activity generated by individual source systems.

```spl
index=main sourcetype=http
| stats count as requests by src_ip
| sort - requests
```

### Investigation Questions

- Which source generated the most requests?
- Are any sources generating unusually high traffic?
- Is the activity expected?

---

## 5. HTTP Requests by URI

Identify frequently requested resources.

```spl
index=main sourcetype=http
| stats count as requests by uri
| sort - requests
```

This can help identify:

- Frequently accessed resources
- Unusual URIs
- Potentially interesting requests
- Resources requiring further investigation

---

## 6. HTTP Requests by Source and URI

Correlate source systems with requested resources.

```spl
index=main sourcetype=http
| stats count as requests by src_ip uri
| sort - requests
```

This provides additional context when investigating unusual HTTP activity.

---

## 7. HTTP Activity Over Time

Analyze HTTP activity using time-based aggregation.

```spl
index=main sourcetype=http
| timechart span=1h count
```

### Investigation Value

This can help identify:

- Traffic spikes
- Unusual activity windows
- Changes in normal traffic patterns
- Potential anomalies

---

## 8. HTTP Activity by Source Over Time

```spl
index=main sourcetype=http
| timechart span=1h count by src_ip
```

This can help identify source systems associated with unusual changes in traffic volume.

---

## 9. Identify High-Volume HTTP Sources

```spl
index=main sourcetype=http
| stats count as request_count by src_ip
| sort - request_count
```

A high request volume can be investigated for:

- Automated activity
- Application behavior
- Crawling
- Misconfiguration
- Potentially suspicious traffic

A high request count alone does not prove malicious activity.

---

# HTTP Response Analysis

## 10. Identify Client Errors

HTTP 4xx responses can be investigated as part of abnormal traffic analysis.

```spl
index=main sourcetype=http status>=400 status<500
| stats count as errors by src_ip status
| sort - errors
```

### Investigation Value

Repeated client errors may indicate:

- Invalid requests
- Authentication problems
- Automated probing
- Application misuse
- Other suspicious behavior

---

## 11. Identify Server Errors

HTTP 5xx responses can be reviewed to identify unusual server-side behavior.

```spl
index=main sourcetype=http status>=500 status<600
| stats count as errors by src_ip status
| sort - errors
```

This can help identify unusual error patterns and systems associated with them.

---

## 12. Analyze Error Activity Over Time

```spl
index=main sourcetype=http status>=400
| timechart span=1h count
```

This can help identify periods with increased HTTP error activity.

---

---

## 13. Identify Sources with High Request Counts

```spl
index=main sourcetype=http
| stats count as request_count by src_ip
| where request_count >= 100
| sort - request_count
```

### Detection Logic

The search:

1. Searches HTTP events
2. Groups requests by source IP
3. Counts requests
4. Applies an example threshold
5. Sorts sources by request volume

> The threshold is an example and should be tuned according to normal traffic behavior.

---

## 14. Identify Sources with High Error Counts

```spl
index=main sourcetype=http status>=400
| stats count as error_count by src_ip
| where error_count >= 20
| sort - error_count
```

This can help prioritize sources generating unusually large numbers of HTTP errors.

---

## 15. Identify High-Volume URI Requests

```spl
index=main sourcetype=http
| stats count as request_count by uri
| where request_count >= 50
| sort - request_count
```

This can help identify resources receiving unusually high request volumes.

---

## 16. Investigate a Specific Source

```spl
index=main sourcetype=http src_ip="<source_ip>"
| table _time src_ip method uri status
| sort _time
```

Replace:

```text
<source_ip>
```

with the source being investigated.

## 17. Investigate a Specific URI

```spl
index=main sourcetype=http uri="<uri>"
| table _time src_ip method uri status
| sort _time
```

<uri>

with the resource being investigated.

# Investigation Checklist

When investigating abnormal HTTP traffic, consider:

- Which source generated the activity?
- How many requests were generated?
- What time period was involved?
- Which URIs were requested?
- Which HTTP methods were used?
- What response codes were returned?
- Are there repeated errors?
- Is the traffic expected?
- Are multiple systems showing similar behavior?
- Does other security telemetry support the finding?
- Does the source require further investigation?

---

# Detection Tuning

HTTP detection thresholds should be tuned according to the normal traffic patterns of the environment.

Factors to consider include:

- Normal request volume
- Application behavior
- Automated services
- Monitoring systems
- Crawlers
- Administrative activity
- Expected error rates

A threshold violation should be treated as an investigation signal rather than automatic proof of malicious activity.

---

# IOC Identification

HTTP analysis can provide potentially useful indicators such as:

- Source IP addresses
- Destination information
- Domains
- URLs
- Suspicious URIs
- Unusual request patterns

Potential indicators should be validated using additional evidence before being classified as confirmed malicious indicators.

- Detect high-volume activity
- Support IOC identification
- Investigate suspicious web activity
