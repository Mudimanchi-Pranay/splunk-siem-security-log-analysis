# DNS Security Analysis – SPL Queries

## Overview

DNS telemetry can provide valuable security information during SOC investigations.

This section contains SPL searches for analyzing DNS activity, identifying frequently queried domains, investigating unusual query behavior, and supporting IOC analysis.

> **Note:** Field names can vary depending on the DNS log source and Splunk data model. The searches below use common field names and can be adapted to the actual ingested dataset.

---

## 1. Search DNS Events

A basic search can be used to identify DNS-related events.

```spl
index=main sourcetype=dns
| table _time src_ip dest_ip query
| sort - _time
```

### Purpose

Provides a basic view of:

- Event timestamp
- Source IP
- Destination IP
- DNS query

---

## 2. Identify Frequently Queried Domains

Repeated DNS queries can be investigated by counting queries for each domain.

```spl
index=main sourcetype=dns
| stats count by query
| sort - count
```

### Investigation Value

This can help identify:

- Frequently queried domains
- High-volume DNS activity
- Domains requiring further investigation

---

## 3. DNS Queries by Source IP

Analyze DNS activity generated by individual systems.

```spl
index=main sourcetype=dns
| stats count by src_ip query
| sort - count
```

### Investigation Questions

- Which systems generated the most DNS queries?
- Which domains were queried?
- Are unusual domains associated with a particular source?

---

## 4. Identify High-Volume DNS Sources

Identify systems generating unusually high numbers of DNS queries.

```spl
index=main sourcetype=dns
| stats count as dns_queries by src_ip
| sort - dns_queries
```

### Purpose

High-volume activity can be investigated for:

- Misconfigured systems
- Automated applications
- Suspicious DNS behavior
- Potentially compromised endpoints

A high query count alone does **not** prove malicious activity.

---

## 5. DNS Activity Over Time

Analyze DNS activity using time-based aggregation.

```spl
index=main sourcetype=dns
| timechart span=1h count
```

### Purpose

Helps identify:

- Activity spikes
- Unusual time periods
- Changes in DNS behavior
- Potential anomalies

---

## 6. DNS Activity by Source

Visualize DNS activity from individual systems.

```spl
index=main sourcetype=dns
| timechart span=1h count by src_ip
```

This can help identify systems with unusual changes in DNS activity.

---

## 7. Investigate Specific Domain

A specific domain can be investigated by filtering the DNS query field.

```spl
index=main sourcetype=dns query="<domain>"
| table _time src_ip query
| sort - _time
```

Replace:

```text
<domain>
```

with the domain being investigated.

---

## 8. Investigate Suspicious DNS Activity

A suspicious DNS investigation can begin by identifying unusual query patterns.

```spl
index=main sourcetype=dns
| stats count values(src_ip) as source_ips by query
| sort - count
```

The resulting domains can then be investigated further using additional evidence.

---

## 9. Identify DNS Queries from a Specific Host

```spl
index=main sourcetype=dns src_ip="<source_ip>"
| table _time src_ip query
| sort _time
```

This can help reconstruct DNS activity associated with a particular endpoint.

## 11. Investigation Checklist

When investigating suspicious DNS activity, consider:

- What domain was queried?
- Which source system generated the query?
- How frequently was it queried?
- When did the activity occur?
- Was the behavior isolated or repeated?
- Are other systems making the same queries?
- Does other telemetry support the finding?
- Does the domain require further investigation?

---

## 12. Detection Considerations

Potential DNS detection opportunities include:

- High-frequency queries
- Unusual query patterns
- Unexpected domains
- Repeated queries from a single endpoint
- Sudden changes in DNS behavior
- Domains associated with suspicious activity

These patterns should be investigated using additional context before being classified as malicious.

---

## Key Takeaways

DNS analysis in Splunk can help a SOC analyst:

- Understand DNS activity
- Identify unusual query patterns
- Investigate source systems
- Detect potential anomalies
- Support IOC identification
- Correlate DNS activity with other security telemetry
